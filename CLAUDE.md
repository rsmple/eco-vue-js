# eco-vue-js

Vue 3 UI kit published to npm as `eco-vue-js`. Also ships a shared eslint config (`eslint/`) and a Tailwind base (`tailwind-base/`).

## Commit messages

- Changes: `ui-kit: <lowercase summary>` — imperative, lowercase after the prefix, no trailing period.
  - `ui-kit: add default slot to WButtonMoreItem`
  - `ui-kit: fix current-title update in WTabs when header is hidden`
  - `ui-kit: prevent backspace/delete from stripping the line container in ContentEditable`
- Version bumps: the bare version as the entire message — `0.13.6`. Nothing else in that commit but the version bump.
- Several related changes may be squashed into one `ui-kit:` commit with comma-separated clauses:
  `ui-kit: do not refocus input on clear, drop min-width for input with prefix, expose before slot in WInputSuggest`

## Release notes

There is no `CHANGELOG.md` — the [GitHub Releases](https://github.com/rsmple/eco-vue-js/releases) page is the changelog.

- Tag and title are both `vX.Y.Z`.
- Body is 2–4 hand-written consumer-facing bullets, each starting with `- `.
- Write what changed for someone using the component, not what the commit did. Start with a verb (`Add`, `Fix`, `Expose`, `Drop`) and name the component:
  ```
  - Fix ContentEditable allowing backspace/delete to strip the line container and corrupt the editor structure
  - Add submitText and disableMinHeight props to WModalStepper
  ```
- Internal-only churn (dependency bumps, lint config, build tweaks) can be a single summary bullet or omitted.

## Release flow

1. Land the change as a `ui-kit:` commit.
2. `npm version <patch|minor|major> --no-git-tag-version`, then commit the bare version (e.g. `0.13.7`).
3. Push `main`.
4. `gh release create vX.Y.Z --title vX.Y.Z --notes "- ..."`

Creating the GitHub release is what publishes to npm — `.github/workflows/npm-publish.yml` runs on `release: created` and does `npm run build` then `npm publish` from `package/`.

`package/package.json` is generated by the build from the root `package.json` — never edit it directly.
